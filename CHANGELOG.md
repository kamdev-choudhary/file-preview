# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project
adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Legacy `.doc` files preview natively.** Previously they fell through to the
  download card, because mammoth reads OOXML and `.doc` is not OOXML — it is an
  OLE2 container of binary records predating the `.docx` package format. There
  is no credible browser library for it, so the library now ships its own
  reader: `src/core/cfb.ts` walks the OLE2 container, and `src/core/doc.ts`
  reassembles the document text from the FIB and its piece table, decoding both
  the Windows-1252 and UTF-16 runs a single file can mix. No new dependency,
  and the viewer is lazy-loaded like every other one.

  Fidelity is **text only** — paragraphs, tables and field results, with no
  formatting. Reading character and paragraph properties would mean a parser
  several times the size for the part of a document a reader can most easily do
  without, so the viewer states the limitation above every document and the
  toolbar still offers the Office viewer when layout matters. Password-protected
  files, Word 6.0/95 documents and `.docx` files misnamed `.doc` each get their
  own specific message instead of a generic failure.

### Fixed

- **Images are centred in the viewport.** Two different elements both answered
  to the `.fp-stage` selector — the element's own mount point, which is
  absolutely positioned at `inset: 0`, and the image viewer's wrapper. The
  cascade merged them, so every image was taken out of flow and pinned to the
  top-left corner where the centring rule could never reach it. The image is
  now the centred flex item itself, with no wrapper in between.
- **Oversized video fits the viewport.** `.fp-video` sizes itself with
  `max-width`/`max-height: 100%`, but its wrapper had no definite height for
  those percentages to resolve against, so a video larger than the viewer
  rendered at its intrinsic size and spilled out behind scrollbars. The player
  now sits directly in the viewport, as the image does.
- **Audio player is centred** rather than stretched across the top-left; it was
  caught by the same selector collision.
- **Zooming scales the fitted image, not the original.** Passing 100% dropped
  the image's fit constraints, so one 125% step on an image that had been
  shrunk to fit jumped it to full natural size — several hundred percent for a
  large photo. Zoom now scales what you can see.

### Changed

- The image stays horizontally centred while zoomed, for as long as it still
  fits across. Only the axis that genuinely overflows anchors to its start
  edge, and that axis scales from that edge so panning reaches the whole
  image. Previously any zoom above 100% threw the image into the corner on
  both axes at once.

## [0.2.0] — 2026-10-16

This release renames the package and rewrites the source in TypeScript. The
runtime API is unchanged apart from the import specifier.

### Changed — breaking

- **Renamed from `@quartix/file-preview` to `fileon`.** Update your imports:

  ```diff
  - import { openPreview } from '@quartix/file-preview';
  + import { openPreview } from 'fileon';
  ```

  The element names (`<file-preview>`, `<file-preview-modal>`), every exported
  function, all attributes and all event names are unchanged.

- **`engines.node` is now `^20.19.0 || >=22.12.0`** (was `>=18`). This only
  affects building the library; the published bundle targets browsers. Node 18
  could never actually build it — Vite 8 requires 20.19+ — so the old range was
  wrong rather than permissive.

### Added

- **TypeScript throughout.** The whole `src/` tree is now `.ts`, and the
  published `index.d.ts` is generated by `tsc` from that source instead of being
  hand-written. Types can no longer drift from the implementation.
- **Many more exported types**: `ViewerContext`, `ViewerInstance`,
  `ViewerDefinition`, `ToolbarAction`, `FileKind`, `FileTypeDescriptor`,
  `SniffResult`, `PreviewErrorCode`, `FileDescriptor`, `SourceDefaults`,
  `ReadOptions`, `ShowOptions`, `XlsxLoader` and more.
- **A test suite** — 297 unit tests covering detection, the CSV parser, the
  `Source` abstraction, the viewer registry, networking and size limits, the
  error taxonomy, config merging, the DOM helpers, the error/loading panels and
  syntax highlighting. There were none before. Every syntax grammar and every
  built-in viewer module is load-tested, so a broken lazy import fails in CI
  rather than in a user's browser.
- **CI** on every push and PR: lint, format check, typecheck, tests with
  coverage thresholds, build, an entry-chunk size budget, `publint` and
  `@arethetypeswrong/cli`, across Node 20.19 / 22 / 24.
- **Tooling**: oxlint, Prettier, a size-budget check (`pnpm size`), and a single
  `pnpm verify` that runs everything CI does.
- `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`, issue and PR
  templates, and a GitHub Pages deployment for the demo.

### Fixed

- **`pdfCMapUrl` and `pdfStandardFontDataUrl` were missing from the published
  `PreviewConfig` type.** Both have always been supported at runtime, but
  TypeScript consumers got an error passing them. This is exactly the drift the
  generated types now prevent.
- **Removed a dead `isEvalSupported: false` option** passed to pdf.js. The
  option was removed in pdf.js v6 (the eval-based rendering path no longer
  exists), so it was being silently ignored. The README's security section
  claimed it was in effect; that claim is now accurate.
- **Removed a no-op `doc.destroy?.()` call** in the PDF viewer.
  `PDFDocumentProxy` has no `destroy` method — the optional chaining meant the
  call did nothing. Teardown goes through the loading task, which does destroy
  the document and its worker transport.
- **Updated the PDF canvas render call** to pass `canvas` rather than
  `canvasContext`, which is the deprecated path in pdf.js v6.
- **`configure()` now returns a deep-copied snapshot.** Previously the returned
  object shared its `loaders` reference with the live config, so a snapshot
  taken before a later `configure()` call would appear to change.
- Dropped a dead `allowScripts` field from `package.json` (left over from
  `@lavamoat/allow-scripts`, which was not installed). Install scripts are now
  allowlisted properly via pnpm's `onlyBuiltDependencies`.
- Removed an unused `config` binding in the spreadsheet viewer.

### Performance

- **Syntax highlighting is ~5× smaller.** The text viewer imported
  `highlight.js/lib/common`, a single 198 kB chunk containing ~40 grammars, for
  every text or code preview. It now loads `highlight.js/lib/core` plus exactly
  one grammar: **~35 kB raw / ~12 kB gzipped** for a JavaScript file, down from
  198 kB / 59 kB.

### Packaging

- Migrated from npm to **pnpm**, with install scripts allowlisted and
  `autoInstallPeers` off. The latter matters: with it on, pnpm installed the
  `xlsx` optional peer automatically, quietly undoing the deliberate decision
  not to ship SheetJS.
- Added `repository`, `bugs` and `homepage`, so the npm page links back here.
- npm **provenance** is enabled for published releases.
- Narrowed the `xlsx` optional peer range from `*` to `>=0.18.5`.
